ATUALIZAÇÃO SISCOM - FORMULÁRIO DE BAIXA AUTOMÁTICO (SOMENTE GET)

1. BANCO SUPABASE: execute no SQL Editor:

ALTER TABLE public.siscom_gateway_jobs DROP CONSTRAINT IF EXISTS siscom_gateway_jobs_operation_check;
ALTER TABLE public.siscom_gateway_jobs ADD CONSTRAINT siscom_gateway_jobs_operation_check
CHECK (operation = ANY (ARRAY['healthcheck','consultar_ss','consultar_eventos_ss','listar_equipes','listar_micros','listar_causas','consultar_ss_baixa']));

IMPORTANTE: os três catálogos já foram liberados anteriormente; a nova operação é consultar_ss_baixa.

2. SITE: copie server.js e public/index.html do ZIP SITE para a raiz do repositório global-ss, mantendo os outros arquivos. Faça git add, commit e push.

3. WORKER: pare o worker com Ctrl+C, faça backup do worker.js atual, substitua pelo worker.js do ZIP WORKER, execute node --check .\worker.js e node .\worker.js.

4. TESTE: no Vercel, Notas para Baixar, selecione exatamente uma SS e clique em Baixar. Digite o token do gateway no campo e pressione Enter. O formulário deve consultar a SS oficial e, em seguida, listar equipes e serviços do macro. O código de equipe pode ser digitado ou escolhido na lista. Selecione o Serviço Executado; Causa do Problema aparece somente se exigida.

5. SEGURANÇA: NÃO inserir tokens em código ou Git. A consulta requer token administrativo temporário, não implementa login individual SISCOM. NÃO envia POST de baixa nem altera situação da SS.

6. Se a unidade executora vier sem cdExecutor ou cdUnidadeExecutora, consulte a resposta oficial para identificar o campo exato. Não presuma 9914 para todas as SS.
